# Межагентная передача контекста

Последнее обновление: 2026-07-08

## Цель сессии

Интегрировать ИИ-анализ результатов диагностики через внешнюю LLM на Open Web UI
(OpenAI-совместимый API): анализ по одному результату, по студенту (портрет)
и по группе (тенденции/риски), по кнопке, с кэшированием в БД и включением в PDF.

## Текущее состояние

- Код фичи реализован и закоммичен на клиентской машине разработки; **на сервере ещё не развёрнут**.
- Сессия велась на клиенте без `.env` и без MySQL, поэтому запуск сервера, интеграционный тест
  и живой вызов LLM локально не выполнялись — это задачи серверного агента (см. раздел ниже).
- Юнит-тесты: 36/36 успешно (6 новых по ИИ-фиче). Синтаксис всех JS: успешно.
  Паритет RU/KZ: 336/336, missing 0. Роуты `/api/ai/*` подняты без БД и вернули 401 без токена.

## ЗАДАЧИ ДЛЯ АГЕНТА НА СЕРВЕРЕ (по порядку)

1. `git pull` в каталоге приложения; убедиться, что HEAD содержит коммит с ИИ-анализом.
2. Добавить в `.env` (по образцу `.env.example`; значения запросить у владельца,
   ключ API создаётся в Open Web UI: Settings → Account → API Keys):
   ```
   OPENWEBUI_BASE_URL=<адрес Open Web UI без завершающего />
   OPENWEBUI_API_KEY=<ключ>
   OPENWEBUI_MODEL=<точное имя модели из Open Web UI>
   OPENWEBUI_TIMEOUT_MS=120000
   ```
   Если переменные не заданы — приложение работает как раньше, кнопки ИИ скрыты.
3. `npm test` — ожидается 36/36.
4. `npm run test:integration` — только с учётной записью MySQL с правами CREATE/DROP DATABASE;
   тест создаёт и удаляет БД с префиксом `psyagent_it_`.
5. Перезапустить процесс (`pm2 restart psyagent`), проверить `pm2 status` → online.
   При старте `syncTenantSchemas()` сам создаст таблицу `ai_analyses` во всех БД колледжей —
   проверить в логе отсутствие ошибок синхронизации схем и при желании
   `SHOW CREATE TABLE ai_analyses` в одной из tenant-БД.
6. Проверить API: `curl http://127.0.0.1:3000/` → 200; под токеном психолога
   `GET /api/ai/status` → `{"enabled":true,"model":"..."}`. Если `enabled:false` —
   проверить, что заданы все три переменные `OPENWEBUI_*` (частичная настройка даёт warn в логе).
7. Живой прогон под психологом: открыть результат → «Сгенерировать ИИ-анализ» → текст приходит,
   повторное открытие модалки отдаёт кэш мгновенно, «Обновить анализ» перезаписывает
   (меняется `created_at`); проверить запись `AI_ANALYZE` в `audit_log`.
8. Проверить скоупинг куратора: чужая группа/студент/результат → 403/404.
9. PDF по студенту с сохранённым анализом содержит секцию «ИИ-анализ»; без анализа — отчёт как раньше.
10. Если модель медленная и ловится 504 — увеличить `OPENWEBUI_TIMEOUT_MS` и перезапустить.
11. Обновить `HANDOFF.md` результатами развёртывания.

## Внесённые изменения

### Бэкенд (`server.js`, `.env.example`)

- Конфиг `OPENWEBUI_BASE_URL/API_KEY/MODEL/TIMEOUT_MS`; фича включается только при полном наборе
  (`AI_ANALYSIS_ENABLED`), частичная настройка даёт предупреждение при старте.
- Таблица `ai_analyses` в `ensureTenantSchema` (scope `result|student|group`,
  `target_id` VARCHAR — id результата/студента или имя группы, `UNIQUE(scope, target_id)`,
  MEDIUMTEXT `content`). Хранится только последний анализ; перегенерация — UPSERT.
  При `DELETE /api/results/:id` анализ результата удаляется.
- `callLlm(messages)` — нативный `fetch` на `{base}/api/chat/completions`, `stream:false`,
  `temperature:0.3`, `AbortSignal.timeout`. Ошибки: 503 «не настроен», 504 таймаут, 502 недоступен/пусто.
- Обезличивание: `buildScoredSummary(row)` строит сводку через `scoreMethodology`
  (шкалы: имя/балл/макс/уровень/метка/attention + предупреждения достоверности).
  **ФИО/логины/контакты в промпт не попадают** — закреплено юнит-тестами. В групповом промпте
  студенты подписаны «Студент 1..N», соответствие номеров реальным студентам не сохраняется;
  лимит 50 студентов с пометкой об усечении.
- Промпты: общая константа `AI_PROMPT_COMMON` (роль ассистента педагога-психолога, только переданные
  данные, структура ответа, оговорка «не диагноз») + билдеры `buildResultPrompt/buildStudentPrompt/buildGroupPrompt`.
- Роуты (`authenticateToken, requireStaff`): `GET /api/ai/status`,
  `GET /api/ai/analysis?scope=&targetId=` (кэш, 200 с `null`), `POST /api/ai/analysis` (генерация).
  Куратор скоупится на свою группу (чужой result/student → 404, чужая группа → 403);
  только `completed`-результаты; параллельная генерация одной цели → 429; аудит `AI_ANALYZE`.
- CSP не менялась: все вызовы LLM серверные, ключ API в браузер не попадает.

### Фронтенд

- Новый `public/ai-analysis.js` (общий для админа и куратора): `window.PsyAi`
  (`initAiStatus/loadAiAnalysis/openModal/reveal`). Текст модели рендерится **только через
  `textContent`** (абзацы + списки), innerHTML не используется — XSS исключён. Спиннер,
  «Сгенерировать»/«Обновить», мета (дата, модель, автор), дисклеймер. Кнопки помечены
  `data-ai-only` и скрыты, пока `/api/ai/status` не подтвердит включение.
- `admin.html/admin.js`: блок анализа в модалке результата (`#resultAiBlock`), кнопка ✨ в строке
  студента, «ИИ-анализ группы» на странице результатов (группа из фильтра `#resultGroup`),
  универсальная модалка `#aiAnalysisModal`.
- `curator.html/curator.js`: «ИИ-анализ группы» в шапке, кнопка ✨ в строке студента, та же модалка.
- `i18n.js`: ключи `ai.*` и `report.ai_section` в обеих локалях (паритет 336/336).

### PDF

- `pdf-download.js buildStudentReport`: `opts.aiAnalysis` — секция «ИИ-анализ» + дисклеймер.
- `admin.js downloadStudentReport/downloadResultReport` и `curator.js downloadStudentReport`
  подтягивают **сохранённый** анализ (без автогенерации); при ошибке отчёт строится без секции.

## Известные ограничения и риски

1. `style-src 'unsafe-inline'` в CSP — прежнее ограничение, не связано с этой сессией.
2. Пароль MySQL короче 12 символов — прежний риск, плановая замена.
3. Переименование группы «осиротит» её групповой анализ (ключ — имя группы);
   приемлемо: анализ перегенерируется по кнопке.
4. Кэш анализа не инвалидируется автоматически при появлении новых результатов —
   психолог видит дату формирования и может нажать «Обновить».
5. Ответственность за качество текста несёт внешняя модель; в системный промпт и UI/PDF
   зашита оговорка «не диагноз, выводы делает специалист».

## Отложенные продуктовые решения

- Методика Кожухарь для педагогов — не начинать без отдельного указания владельца.
- Методика Ракишевой — ждёт исправленного официального ключа.
- Тарифы/подписка, лендинг/демо/триал и согласия ПДн отложены владельцем.
