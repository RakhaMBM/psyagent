## Production-инцидент после развёртывания

- После `git pull` и перезапуска Nginx стал возвращать 502, потому что процесс Node вошёл в цикл падения.
- Точная ошибка PM2: `DB_PASSWORD должен быть уникальным секретом длиной не менее 12 символов`
  (`server.js:38`).
- Причина: существующий рабочий пароль MySQL короче 12 символов, а новая проверка ошибочно блокирует
  запуск приложения. Это не ошибка Nginx, подключения к БД или миграции.
- Постоянный hotfix внесён локально: в production по-прежнему требуется непустой `DB_PASSWORD`,
  демонстрационные placeholder-значения отклоняются, а короткий существующий пароль теперь только
  вызывает предупреждение. После восстановления пароль MySQL рекомендуется планово заменить на
  сильный с учётом всех потребителей.
- Добавлен регрессионный тест короткого legacy-пароля и placeholder. После hotfix проходят 21/21 тест,
  отдельно проверена загрузка `server.js` с `NODE_ENV=production` и коротким `DB_PASSWORD`.
- Альтернатива без изменения кода — сразу сменить пароль MySQL-пользователя на 12+ символов, одновременно
  обновить `.env` и перезапустить PM2. Перед этим нужно проверить host-запись пользователя и отсутствие
  других приложений, использующих те же реквизиты.

## Основные изменения

### Безопасность и запуск

- Удалены известные пароли и секреты по умолчанию. Добавлен `.env.example`.
- В production обязательны сильные `JWT_SECRET`, `DB_PASSWORD`, `SUPERADMIN_PASSWORD`.
  В development при отсутствии `JWT_SECRET` создаётся временный случайный ключ.
- Первый психолог создаётся отдельной командой `npm run create-admin`; пароль в журнал не выводится.
- Запуск HTTP начинается только после успешной инициализации control-БД, БД колледжей и схем.
- Добавлены защитные HTTP-заголовки и CSP, ограничение JSON-тела 5 МБ, обработка слишком большого
  и некорректного JSON.
- Добавлено ограничение неудачных входов: 8 попыток за 15 минут на IP.
- JWT хранит только идентификаторы. Роль, группа, активность пользователя и колледжа повторно
  проверяются в БД на каждом запросе.
- `token_version` отзывает старые токены после смены/сброса пароля и деактивации пользователя.

### Целостность назначений и результатов

- `results` связан с конкретным `assignment_id`; добавлены уникальность и внешний ключ.
- Назначение валидирует тест, студентов и срок, выполняется транзакционно, не создаёт второй
  открытый дубль, но разрешает повторное прохождение после завершения.
- Старт, сохранение и завершение доступны только студенту по действующему назначению.
  Просроченные назначения переводятся в `expired`.
- Завершённый результат нельзя изменить повторно.
- Сервер проверяет обязательность и допустимость single/multiple/scale/text-ответов.
- Черновик восстанавливает сохранённые ответы.
- Вопросник сохраняет снимок `methodology_data`; исторический результат больше не зависит от
  последующего изменения или удаления пользовательской методики.
- Клиент и сервер используют один движок подсчёта. Резервный подсчёт ручных тестов поддерживает
  веса single/multiple и среднее для шкальных вопросов.

### Движок и встроенные методики

- Движок поддерживает суммы, средние, множитель, итоговую/агрегатную шкалу, выбор `totalScale`,
  пересекающиеся шкалы, обратные вопросы, скрытые служебные подшкалы и шкалы достоверности.
- Встроены 11 методик: Рассел, Корчагина, Хмельницкая, Мадди, Янг, Олвеус, Рифф, Бек,
  Кук—Медли, Розенберг, Кожухарь для подростков.
- Для каждой новой формулы добавлены проверки граничных значений, обратных и пересекающихся шкал.
- Цвет результата теперь определяется `attention`, а не словом `high`: высокий уровень
  благополучия/жизнестойкости отображается положительно.

### Методики, которые сознательно не автоматизированы

- Версия Кожухарь для педагогов требует отдельного режима респондента-сотрудника.

## Известные ограничения и риски

1. CSP пока содержит `'unsafe-inline'`, потому что страницы используют inline-скрипты и обработчики.
   Сохранённый XSS экранирован, но для строгой CSP нужно вынести скрипты и обработчики в отдельные файлы.
2. В `tmp/pdfs/` остались игнорируемые PNG, использованные для визуальной сверки PDF:
   удаление было отклонено политикой файловой песочницы. В Git они не входят.
3. PM2 показывает 53 исторических рестарта; последние ошибки относятся к устранённой блокировке
   короткого DB-пароля. Текущий процесс стабилен, но пароль MySQL всё ещё рекомендуется усилить.
4. UI-проверка использовала реальные страницы и тестовые ответы API в браузере; полный REST-сценарий
   отдельно проверен интеграционным тестом. Единый browser-to-database e2e пока не автоматизирован.
